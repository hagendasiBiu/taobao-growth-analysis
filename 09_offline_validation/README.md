# 淘宝未购意向人群的离线名单策略验证

本次补充验证回答一个具体问题：**在只能优先选择1,000人的条件下，能否比随机选择更集中地识别未来两天会购买的用户？**

主测试中，验证集选定的“按最近一次收藏或加购时间排序”规则，在1,000人名单中覆盖281名后续买家。同一候选池随机抽取1,000人的理论期望为213.22名，名单命中率由随机基线期望21.32%提高到28.10%，相差6.78个百分点、相对高31.79%。

这是**未来买家识别和名单覆盖的离线结果**。没有发券或触达，没有真实随机分配干预，不证明额外创造了约68名买家，也不证明转化率、GMV或ROI受到策略改善。

## 验证设计

分析计划保存在 `protocol.json`，在本次运行候选规则评价前固定。它是既有历史数据的回溯分析计划，不是前瞻性预注册，也不构成真正封存的盲测。

| 窗口 | 提取特征的日期 | 观察购买的日期 | 用途 |
|---|---|---|---|
| 验证集 | 11月25至27日 | 11月28至29日 | 比较五个固定候选规则并选定一条 |
| 主测试 | 11月25至29日 | 11月30日至12月1日 | 使用选定规则评价，不再调参或换规则 |
| 周末检查 | 11月25日至12月1日 | 12月2至3日 | 不改规则，检查后续周末表现 |

日期均为2017年北京时间。三个结果窗口互不重叠；历史窗口逐次扩展。不同窗口可能包含相同用户，因此周末结果是时间上的延续检查，不是独立用户样本的重复实验。

**候选池定义：**决策前已在数据中出现，历史窗口中没有buy事件，且至少有一次fav或cart。它不是平台注册新客，也不是从完整九天的未购用户中倒推人群。决策后的购买只用于标签，不用于选人。

**标签：**后续两个完整自然日内至少有一个buy事件；可以是任意商品，不能解释为原收藏或加购商品的转化。无购买记录记为0，仅表示源日志窗口内未观察到购买。

**容量：**主结果固定1,000人，另外报告500和2,000人；这是假设的运营处理容量，不是已经执行的触达量或实际营销预算。

**规则：**最近意向时间、收藏加购总次数、加购次数、最近活跃时间、浏览次数。按分数降序，平分时用与未来标签无关的固定用户哈希排序。以验证集1,000人名单命中率最高者为选定规则；若规则同分，按计划中的固定顺序选择。

## 基线和指标

主基线为在**同一个未购意向候选池**中，不放回地等概率抽取相同人数，避免仅仅把全体未购用户缩小到意向人群就声称排序有效。

设候选池N人，其中未来买家M人，选k人：随机名单期望命中买家为k×M/N，随机名单期望命中率为M/N。没有从许多随机种子中挑表现较差的基线。

- 名单命中率Precision@k＝名单中的后续买家数/k。
- 买家覆盖率Recall@k＝名单中的后续买家数/候选池后续买家数。
- 相对随机优势＝策略命中率/随机期望命中率－1。
- 覆盖差额＝策略覆盖买家数－随机期望覆盖买家数，不能称为营销新增买家。

附加报告“所有历史未购用户中的随机选择”只作宽人群参考，主结论始终采用同一意向候选池的随机基线。

## 主结果

| 指标 | 主测试 | 周末检查 |
|---|---:|---:|
| 决策前历史未购买用户 | 25,554 | 20,743 |
| 其中符合意向条件的候选人 | 16,504 | 15,122 |
| 候选池后续两天买家 | 3,519 | 3,746 |
| 策略选定名单人数 | 1,000 | 1,000 |
| 名单中后续买家 | 281 | 319 |
| 同容量随机名单期望买家 | 213.22 | 247.72 |
| 策略名单命中率 | 28.10% | 31.90% |
| 随机名单期望命中率 | 21.32% | 24.77% |
| 命中率差 | 6.78个百分点 | 7.13个百分点 |
| 命中率相对优势 | 31.79% | 28.78% |
| 额外覆盖的已观测买家 相对随机期望 | 67.78 | 71.28 |
| 策略覆盖候选池买家的比例 | 7.99% | 8.52% |

1,000人名单在主测试中只覆盖候选池3,519名买家中的281名，说明有限容量下有排序价值，也意味着多数后续买家仍未被覆盖。

按固定随机种子模拟10,000次不放回抽样，主测试随机名单覆盖买家数的2.5%至97.5%分位区间是189至238人，周末为223至273人。它描述**在既定样本标签下随机名单的波动**，不是因果效果的置信区间，也不是策略在所有未来月份表现的置信区间。

## 所有候选规则的对照

| 固定1,000人 | 验证集命中买家 | 主测试命中买家 |
|---|---:|---:|
| 最近一次收藏或加购时间 | 314 | 281 |
| 收藏与加购总次数 | 271 | 257 |
| 加购次数 | 313 | 289 |
| 最近一次任意活跃时间 | 274 | 273 |
| 浏览次数 | 249 | 220 |

验证集中的最近意向规则只比加购次数规则多1名买家；主测试中加购次数规则反而多命中8人，即28.90%对28.10%。因此结论是“验证集选定的简单规则在后续窗口优于随机基线”，**不是“找到最优规则”或“优于所有常用方法”**。本次没有看到测试结果后改选加购次数并把它当作原定主策略。

## 容量敏感性

| 窗口 | 选择人数 | 命中买家 | 命中率 | 相对同池随机期望 |
|---|---:|---:|---:|---:|
| 主测试 | 500 | 138 | 27.60% | +29.44% |
| 主测试 | 1,000 | 281 | 28.10% | +31.79% |
| 主测试 | 2,000 | 544 | 27.20% | +27.57% |
| 周末 | 500 | 162 | 32.40% | +30.79% |
| 周末 | 1,000 | 319 | 31.90% | +28.78% |
| 周末 | 2,000 | 622 | 31.10% | +25.55% |

三个容量都保留相对随机优势，但命中率并非容量越小越高；容量只是资源约束情景，没有成本或利润数据支持“最佳投放预算”的结论。

## 怎样用于运营决策

结果支持把最近发生收藏或加购的未购用户作为**进一步验证的优先人群**，也支持与按加购次数排序作并行对照。若目的是提醒承接，可用名单做试验入口；若目的是发券，不能直接认为高自然购买概率用户更值得补贴，因为他们可能本来就会购买。

要证明优惠券或提醒创造了增量，需要在同一入选人群内随机分配干预并比较结果，见 `live_experiment_plan.md`。历史日志不含干预分配、券成本、订单金额和毛利，本次无法执行真实线上实验或估计净收益。

## 复现与检查

从项目根目录运行：

```bash
python 09_offline_validation/test_validation.py
python 09_offline_validation/run_validation.py
python 09_offline_validation/independent_check.py
```

输入沿用本地 `02_processed_data/UserBehavior_clean.csv`，不上传原始或逐人明细。只依赖Python标准库、NumPy和Pandas。代码记录输入文件SHA256、计划SHA256及库版本，以便追溯。本次使用约496万条日志完整运行，3项边界/泄漏测试通过；另用标准库CSV流式处理实现独立核对，验证与主测试的五种规则以及周末主规则的1,000人结果全部一致。

输出位于 `results/`：`strategy_comparison.csv`包含全部对照与容量情景；`window_summary.csv`包含窗口人数；`results.json`是主要结果；`independent_check.json`保存交叉核验结果。

## 简历可用表述

**离线策略验证：**针对促转人群缺少优先级与效果基线的问题，按时间划分验证与测试窗口，对比5种行为规则，并在固定1,000人容量下评价未来两天买家识别；验证集选定的最近意向规则在后续测试中覆盖281名买家，较同池随机名单理论期望213名高31.8%，名单命中率由随机期望21.32%提高至28.10%；补充500/2,000人容量及周末窗口检查。

此处提高的是**离线名单命中率，相对于随机期望**，不是发券后真实转化率。面试需说明加购次数基线在主测试中略优，且当前尚未证明干预增量。
